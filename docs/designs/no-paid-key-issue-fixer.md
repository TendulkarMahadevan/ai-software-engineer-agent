## Problem Statement
Turn a GitHub issue into a tested patch on any repo, as an open-source project that earns GitHub stars. Hosted AI APIs charge every user, so the promise people can try is "works with no paid key": choose free local (Ollama), a free hosted tier, or your own paid key, and switch any time with `python main.py --setup`.

## What Makes This Cool
- No key, no bill: a first run on a laptop with a local model.
- Conservative by design: if tests can't run or fail, it shows a diff but never writes PR text claiming a fix.
- Detects and runs tests for Node, Python, Go, Rust, Java and Ruby projects. Only Python, JavaScript and Go are verified by the eval; Rust, Java and Ruby are detection-only and untested, and the README says so.

## Constraints
- Small local models are the weak link: they truncate files, add prose, and need small prompts.
- Target-repo install and test commands run on the user's machine (no sandbox yet).
- Free-tier limits and default model names change often; the README must link to provider docs instead of quoting numbers.
- Solo builder; goal is stars, not revenue.

## Premises
1. The star-worthy promise is "works with no paid key", not "smarter than Devin". (agreed)
2. Trust comes from proof: one representative demo plus an honest pass rate on 5-10 issues. (agreed)
3. Before the demo the agent needs the related-files context fix and a safer edit format (search/replace instead of whole-file rewrites). (agreed)
4. Order of work: demo GIF (Next Steps 5), then `pipx install` (Next Steps 6), then GitHub Action (which needs PR creation and a sandbox first). (agreed)
5. The agent stays conservative: no PR text when tests cannot run or fail. (agreed)

### Approach C: Scoreboard first

## Recommended Approach

## Success Criteria
- Mini-eval method: 5 issues, 3 runs per issue per tier (15 runs per tier). A run passes only if the repo's own tests pass after the patch AND the patch touches the expected file. Results are reported as k/15 with the sample size and a variance caveat, never as a bare percentage.
- Tiers: local Ollama (free, run on your machine); one free hosted tier using your own free key (quota limits noted in the README); a paid tier is optional, uses your own key with one small model and a spend cap you set, and is marked "not measured" if skipped.
- README quotes the measured numbers only, with the Next Steps 0 baseline (local tier, k/15) next to the post-fix local-tier k/15. Free hosted and paid tiers have no baseline and are reported only after the fixes.
- A recorded demo of the agent fixing one real issue on a local model, reproducible by a stranger following the README.
- No PR text is ever produced for a patch whose tests did not run and pass.
